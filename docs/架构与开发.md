# 架构与开发

## 一套状态，两个入口

```text
本地网页 ── HTTP API ──┐
                      ├── app/core.py ── config / SQLite / reports
Hermes ── tide.py CLI ─┘
```

- core.py：公司解析、RSS/Atom、来源发现、SEC、行情、去重、时间窗口、报告、通知。
- server.py：本机 HTTP 服务、任务进度、设置校验、每日调度。
- agent_bridge.py：独立 HERMES_HOME、显式凭证环境、轮数和超时限制。
- web/：静态 HTML/CSS/JS，无 CDN、无远程字体、无前端打包。

## 数据边界

默认运行目录是项目根目录，`TIDE_HOME` 可指定其他目录。根目录下 examples 是公开模板，首次启动复制到 config；之后不自动覆盖用户设置。

报告有 demo 标记。演示不进入 items 表、不替换 latest_live。真实采集插入 SQLite，以 URL 的 SHA256 去重；报告筛选发布时间最近 24 小时的内容。当前只做同 URL 去重，不承诺跨媒体语义聚类。SEC 文件仅采集元数据，未解析全文。

时间精度受源限制：SEC filingDate 按天处理。网页缺时间不冒充采集时间。行情按有效时间戳取最新价格，不固定优先盘前/盘后价格。

网页的任务队列串行运行，防止多次点击重复执行。CLI 和网页共用配置；不要同时运行多个实例或让外部程序并发改 config。SQLite 事务保护历史写入，JSON 用原子替换避免半文件。

## 安全边界

监听 127.0.0.1；校验 Host、同源请求和随机会话令牌；不支持 CORS。CSP 禁止外部脚本和 iframe 嵌套。报告渲染先转义，禁止新闻 HTML 执行。

来源只接受 HTTP/HTTPS 标准端口，解析域名时拒绝内网、回环、元数据地址，并校验重定向。此工具是单机应用，不是面向不可信远程用户的抓取服务；DNS 检查并非完整的网络沙箱。

密钥写入 data/secrets.json，Unix 权限 0600，不通过状态 API 回显。模型接口禁止重定向，避免认证头跟随跳转。模型 endpoint 可以显式配置为本机 HTTP 供本地模型使用。

Agent 当前使用终端与文件工具，不是强制权限沙箱；工作契约不可代替系统隔离。

## 扩展来源

优先使用现有 add-source，绝大多数 RSS 不需要代码。特殊网页适配器需要开发者实现并接入采集流程，补离线响应 fixture、字段提取测试、空内容与失败测试，才能发布。不要把任意抓取代码写进 sources.json。

## 开发和验证

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q app tide.py scripts
python3 tide.py report --demo
python3 tide.py web --port 8766
```

重要用例：源失败不阻断、无日期不当新新闻、去重、模型失败降级、密钥不回显、飞书成功后去重、HTTP 同源保护、Agent 独立 home。

## 发布

```bash
python3 scripts/build_release.py --output dist
```

脚本仅导出明确允许的代码、文档、模板与测试，永远不打包 config/*.json、data、reports、logs、.tools、.git 或 .env。包内附文件校验清单，包外附 ZIP SHA256。发布前把 ZIP 解压到空目录再次运行测试和演示。CI 在 Linux/macOS/Windows 上运行基础测试，不代表 Hermes 三平台都验证过。
